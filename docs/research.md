# ECHO: исследование похожих проектов

Дата съёмки: 5 сентября 2026.  
Репозиторий ECHO на момент съёмки пустой (`# ECHO`).  
Источники: публичные репозитории, документация, npm, сайт [timaxlacs.github.io](https://timaxlacs.github.io), GitHub API по аккаунту `TimaxLacs` и связанным организациям.

Это не обзор «всех голосовых ИИ». Фильтр один: насколько проект близок к тезису ECHO и чему у него можно научиться, прежде чем писать код.

## Тезис, относительно которого всё сравнивается

ECHO — универсальный агент, с которым говорят вслух. Он отвечает **голосом владельца**, а по роли ведёт себя как Джарвис: помнит контекст жизни, умеет действовать, а не только болтать.

Три оси, без которых сравнение разъезжается:

| Ось | Вопрос | Типичный провал рынка |
|---|---|---|
| Присутствие | Разговор живой? Можно перебить? Пауза не считается концом фразы? | Каскад STT→LLM→TTS с дырой в 1–2 секунды |
| Действие | Он делает почту, календарь, дом, браузер, код — или только отвечает? | Красивый голос без рук |
| Идентичность | Это *твой* голос и *твоя* память — или чужой персонаж? | Майя, Джарвис, Алекса: чужое лицо, чужой тембр |

Почти никто не закрывает все три оси сразу. Коммерческие S2S-модели выигрывают разговор и проигрывают «это я». OpenClaw выигрывает руки и проигрывает голос. Локальные Jarvis-клоны часто умеют клонировать тембр, но ломаются на barge-in, памяти и инструментах.

## Как устроен рынок в 2026

Шесть кластеров. Проекты из разных кластеров нельзя сравнивать как будто они делают одно и то же.

```
                    говорит как человек
                           ▲
           Sesame Maya     │     GPT-Live / Gemini Live
           Hume EVI        │     ElevenLabs Conv. AI
                           │
   идентичность ───────────┼─────────────────── действие
   (твой голос,            │
    твоя память)           │     OpenClaw
           InnerEcho ●     │     PersonalJarvis
           ECHOME          │     Open Interpreter
           Limitless       │     Home Assistant Assist
                           │
                           ▼
                    локальный / приватный контур
              isair/jarvis · jarvis-v3 · HA · OVOS · Rhasspy
```

### 1. Разговор как продукт

Сезам (Maya / Miles / Simone / Charlie), ChatGPT Voice → GPT-Live, Gemini Live, Hume EVI.

Делают одно: чтобы с машиной хотелось говорить. Память и инструменты у них либо тонкие, либо закрыты экосистемой. Клона *твоего* голоса как сути продукта нет.

### 2. Джарвис как руки

[OpenClaw](https://openclaw.ai) (бывший Clawdbot / Moltbot), [PersonalJarvis](https://personaljarvis.ai), [Open Interpreter](https://github.com/openinterpreter/openinterpreter), [OpenHands](https://github.com/OpenHands/OpenHands), ZeroClaw.

Агент живёт в мессенджерах и на машине: почта, календарь, браузер, шелл, cron. Голос — надстройка, часто каскад или плагин.

### 3. Голос дома

Home Assistant Assist, OpenVoiceOS, Rhasspy, [Jarvis Automation](https://docs.jarvisautomation.dev) (alexberardi), OHF-Voice.

Сильная сторона — устройства, wake-word, оффлайн, дешёвые сателлиты. Слабая — «второй мозг жизни», если это не HA+LLM. У Jarvis Automation редкая фича: **кто говорит**, а не только что сказано.

### 4. Локальный голосовой контур

[isair/jarvis](https://github.com/isair/jarvis), [CarverXx/jarvis-v3](https://github.com/CarverXx/jarvis-v3), Fulloch, InnerZero, Hugging Face [speech-to-speech](https://github.com/huggingface/speech-to-speech).

Собирают петлю: VAD → STT → LLM → TTS, иногда с клоном. Качество реализации прыгает от «можно жить» до «микрофон молчит, в issues сто человек».

### 5. Голос как слой, не продукт

ElevenLabs, Cartesia, Deepgram, Gradium, Zonos, Chatterbox, CosyVoice, Fish Speech, XTTS, Kokoro, Whisper / faster-whisper, Silero VAD.

Это двигатели. ECHO будет их потребителем, не конкурентом.

### 6. Каркас, на котором собирают агентов

[Pipecat](https://github.com/pipecat-ai/pipecat), [LiveKit Agents](https://github.com/livekit/agents), Vapi / Retell, OpenAI Agents SDK + Realtime.

Не Джарвис. Сантехник: транспорт, очереди кадров, turn-taking, SIP, WebRTC.

Рядом, но не в топе ECHO: Limitless / Rewind (память дня, не агент), screenpipe (локальная история экрана), Mem0 (слой памяти), Stanford [OpenJarvis](https://github.com/open-jarvis/OpenJarvis) (исследовательский стек on-device, не продукт для разговора).

## Как это реализовано: четыре архитектуры

### A. Каскад STT → LLM → TTS

Классика 2023–2025 и почти весь опенсорс, включая InnerEcho.

```
мик → VAD → договорить → Whisper → текст → LLM → текст → TTS → колонка
```

Плюсы: любую стадию можно заменить; клон голоса ставится на TTS; тулы считаются по тексту; дешевле.  
Минусы: теряется просодия (вопрос, сарказм, «ну…»); latent 700–1500 мс на хорошем железе; перебить говорящего больно; пауза = конец реплики.

Так живут isair/jarvis, HA Assist, OpenClaw Talk Mode, Vapi-каскад, InnerEcho.

### B. Нативный speech-to-speech

Одна модель ест звук и выдаёт звук. GPT-4o Realtime, Gemini Live, Sesame CSM.

Плюсы: 250–700 мс, живая интонация, естественные перебивания.  
Минусы: голос — из каталога модели, не твой; тулы хуже, чем у текстового LLM; дорого; русский слабее английского; закрытый вес.

### C. Full-duplex + делегирование

GPT-Live (лето 2026) и в более слабом виде Gemini Live.

Голосовая модель слушает и говорит одновременно. Тяжёлую работу (поиск, рассуждение, агент) отдаёт фоновой frontier-модели, не затыкая разговор. OpenAI прямо пишет: turn detector убрали из аудиопути, решения «молчать / вставить hmm / перебить / позвать инструмент» принимаются много раз в секунду. Транспорт — WebRTC.

Это планка разговора, которую локальный каскад не догонит в 2026. Догонять её в лоб — ошибка. Правильный ход: **быстрый голосовой контур + делегирование рук**, как у PersonalJarvis и у самого GPT-Live.

### D. Шлюз каналов + навыки

OpenClaw: один Gateway на машине, плагины каналов (Telegram, WhatsApp, Discord, iMessage, Signal, Slack…), сессии, память файлами, cron, браузер, шелл.

Голос здесь — ещё один канал, не центр. Память — не векторная магия, а ярусы файлов:

| Ярус | Где | Кто пишет | Когда попадает в контекст |
|---|---|---|---|
| Инструкции | `AGENTS.md` | человек | всегда |
| Ядро | `MEMORY.md`, `USER.md` | консолидация / по просьбе | в начале сессии |
| Эпизод | `memory/YYYY-MM-DD.md` | агент по ходу | по поиску |
| Намерения | SQLite + cron | tool `intent` | когда сработал триггер |

Ночью «сновидение» сжимает день в ядро. Это гораздо ближе к Джарвису, чем ещё один RAG-чат.

## Топ по качеству реализации

Здесь не «насколько Джарвис», а насколько это можно развивать: архитектура, тесты, документация, граница модулей, сообщество, честность про ограничения.

### Первый ряд — воровать паттерны, не копировать бренд

1. **Pipecat** (~15k ★)  
   Голос как конвейер процессоров. Любой STT/LLM/TTS. Transport-agnostic: Daily, LiveKit, SIP, WebSocket. Smart turn detection. Это правильная форма голосового ядра ECHO, если остаётесь на каскаде.

2. **LiveKit Agents** (~14k ★, транспорт ~20k)  
   WebRTC как данность. Комнаты, SIP, запись, несколько участников. ChatGPT Voice сидит на этом транспорте. Брать, когда появится звонок, вебка или «Эхо в браузере», не на первый локальный стенд.

3. **OpenClaw** (~389k ★)  
   Самый зрелый personal-assistant runtime 2026 года: шлюз, плагины, сессии, память ярусами, каналы, skills. Голос пока вторичен и местами сырой (Talk Mode без нормального streaming). Качество *платформы* высокое, качество *разговора* — нет. Форк `TimaxLacs/openclaw` уже лежит.

4. **Home Assistant Assist**  
   Эталон «быстрый локальный матчер, потом LLM». Десять лет интеграций. Не пытаться переписать. Подключить.

5. **deep-assistant/api-gateway** (твоё, в проде)  
   Единственный из списка, который уже пережил реальных пользователей, биллинг и фолбэк 12–16 моделей. Как голосовой продукт слаб, как *мозговой шлюз* — самый качественный код в твоей линейке.

### Второй ряд — сильная идея, меньше обкатки

6. **isair/jarvis** (~1.7k ★)  
   Цельный десктопный ассистент: wake-word в любой фразе, память, MCP без «context rot», редaction секретов перед записью на диск, Piper из коробки, Chatterbox с клоном из исходников. Выглядит как продукт, не как ноутбук с README.

7. **PersonalJarvis**  
   Слои L0–L7, EventBus, риск-политики, Ack-Brain < 1 с, критика ×3, харнессы Claude Code / Codex / OI / MCP. Звёзд мало, но это лучшее *описание* того, как Джарвис должен быть разрезан. Код молодой (с мая 2026).

8. **Jarvis Automation**  
   Speaker ID, pantry пакетов, sandbox на публикации, ноды на Pi Zero за $15–25, AGPL+Apache. Честный пост «мы не HA». Мало звёзд, мысль о «кто говорит» — обязательная к прочтению.

9. **jarvis-v3**  
   Dual-brain на одной машине: быстрый LLM болтает, Hermes/агент делает. VoxCPM2 клонирует с 4–8 сек. Честный local-first. Маленький репозиторий, схема правильная.

10. **LightRAG + твой lightrag-mcp**  
    Память граф+вектор, режимы mix/hybrid/local/global, ссылки на источники, zod-валидация, тесты на `node --test`. Для ECHO это готовый слот «долговременная память», не надо писать свой RAG.

### Третий ряд — не строить с нуля, знать пределы

| Проект | Качество | Предел |
|---|---|---|
| OVOS / Rhasspy | Инженерно честные, старые контракты | Потолок — интенты. LLM прикручен сбоку |
| Open Interpreter / OpenHands | Отличные агенты за клавиатурой | Нет голосовой петли |
| Mem0 | Зрелый memory SaaS/OSS | Слой, не ассистент |
| Stanford OpenJarvis | Исследовательская платформа, энергия/FLOP как метрики | Не продукт «поговори со мной» |
| HuggingFace speech-to-speech | Честный открытый S2S-конвейер | Демо, не жизнь |
| Vapi / Retell | Быстрый телефонный агент | Чужой биллинг, lock-in |
| ECHOME / большинство GitHub «Jarvis» | README обещает зеркало личности | Кода на продукт нет |
| InnerEcho | Честный прототип петли | Главный цикл захардкожен, агент-заглушка |

### Что считается плохой реализацией в этом жанре

Повторяется из репозитория в репозиторий:

- энергия вместо Silero VAD;
- «помолчал 2 секунды — значит конец»;
- Whisper `base` на русском;
- reasoning-модель (DeepSeek-R1 и подобное) в голосовом контуре — она думает вслух и опаздывает;
- TTS пишет wav на диск и играет mpg123, без стрима;
- микрофонный цикл и LLM в одном файле;
- нет wake-word, слушает всегда;
- нет тестов на обрыв, тишину, короткий звук, пустую транскрипцию;
- клон голоса «из любого wav», без проверки что это речь владельца.

InnerEcho содержит почти весь этот список. Это нормально для исследования 2025 года и неприемлемо как фундамент ECHO без пересборки.

## Разбор лидеров: что делают и как собраны

### OpenClaw — руки Джарвиса

Один процесс-шлюз на твоей машине. Сообщение из WhatsApp/Telegram/Discord попадает в агента, агент дергает инструменты, отвечает в тот же канал.

Как сделано:

- канал владеет транспортом, не мозгом;
- провайдер владеет LLM / speech / realtime и регистрируется в слот;
- память — файлы плюс SQLite, не «весь чат в промпт»;
- голос: STT (Whisper) на входящие войсы, TTS (Edge / ElevenLabs) на ответ; Talk Mode — отдельный каскад; voice-call — SIP/Twilio;
- iOS/Android node: камера, canvas, устройство.

Почему это важно ECHO: не писать Telegram, cron и браузер заново. Шлюз — харнесс. Эхо — голос и идентичность сверху.

Риск: продукт легко превратить в «ещё один скин OpenClaw». Тогда пропадает единственное, чего у них нет — *твой* голос как суть.

### GPT-Live / Gemini Live / Sesame — рот Джарвиса

Общее: нативный звук, низкая задержка, характер.

Различия, которые влияют на копирование:

| | GPT-Live | Gemini Live | Sesame |
|---|---|---|---|
| Диалог | full-duplex, hmm/пауза | full-duplex, шум держит лучше | самый «человечный» |
| Руки | делегат на GPT-5.5, тулы зрелые | экосистема Google | тулы слабые |
| Память | аккаунт ChatGPT | аккаунт Google | память *на персонажа*, не общая |
| Голос | каталог OpenAI | каталог Google | 4 персонажа |
| Русский | средний | средний/лучше | почти нет |

Что украсть: не модель, а **разделение**. Голосовой контур никогда не должен ждать, пока агент сходит в почту. Сначала «секунду, смотрю», потом результат в разговор.

### isair/jarvis — ближайший цельный аналог

Локальный десктоп. Обращение по имени в любой фразе, не только «hey». Память, экран, Chrome, MCP, питание, поиск. TTS: Piper по умолчанию, Chatterbox с клоном из wav. Секреты вычищаются до записи на диск.

Архитектура — каскад плюс инструменты. Нет full-duplex. Английский в приоритете. Для ECHO это референс *сборки продукта*, не голосовой магии.

### PersonalJarvis — как резать слои

```
L7 UI (desktop / orb / tray)
L6 оркестратор (router, mission, state machine)
L5 харнесс (Claude Code, Codex, OI, MCP, computer-use)
L4 мозг + Ack-Brain
L3 риск / апрув
L2 wake → VAD → STT → TTS
L1 устройства
L0 ОС
```

Слои общаются шиной, не импортами. Именно поэтому у InnerEcho всё слиплось: микрофон, ffmpeg, LangChain и Zonos в одном `index.js`.

### Jarvis Automation — кто говорит

Единственный self-hosted, который в 2026 честно ставит speaker identification в центр: память, плейлист, таблетки, календарь — *чьи*. HA и Rhasspy это до сих пор feature request.

Для ECHO «твой голос на выходе» и «узнать тебя на входе» — пара. Иначе в комнате с двумя людьми клон начнёт отвечать не тому.

### ElevenLabs Conversational AI

Облачный агент с лучшим клоном. Если нужен wow-демо за день — через него. Если ECHO про локальность и «это я, не корпорация» — только запасной провайдер в шлюзе.

### Home Assistant / OVOS / Rhasspy

Брать как дом и как сателлит (Wyoming, ESPHome, Pi). Не брать как характер и память жизни.

## Что уже сделано у тебя

Снято с [timaxlacs.github.io](https://timaxlacs.github.io), GitHub (`TimaxLacs`, `deep-assistant`, `deep-foundation`) и исходников. Ниже — не резюме сайта, а пригодность для ECHO.

### Прямое попадание: голосовой контур

**[InnerEcho](https://github.com/TimaxLacs/InnerEcho)** (март 2025, JS, прототип)

Собрана правильная петля на бумаге:

1. ALSA-устройства через ffmpeg, тест микрофона.
2. Energy VAD, тишина 2 с.
3. `nodejs-whisper`, модель `base`, язык `ru`.
4. Ollama `deepseek-r1:1.5b` через LangChain.
5. ZonosJS + `reference.wav` → воспроизведение mpg123.

`init.sh` ставит ffmpeg, whisper-модель, Ollama, тянет DeepSeek, поднимает `zonosjs serve` на 5050.

Что сломано в коде, не в идее:

- в `mainLoop` микрофон закомментирован, на вход всегда путь к `reference.wav`;
- ответ LLM заменён на строку `"привет"`;
- ReAct-агент создаётся, в цикле не вызывается, единственный tool — заглушка `semantic`;
- reasoning-модель в голосовом контуре;
- Linux/ALSA only;
- нет стрима, нет wake-word, нет памяти, нет тестов.

Это исследование, которое доказало: «локально клонировать голос и ответить» у тебя уже получалось. ECHO не должен расти из этого файла. Он должен вырасти из *урока*.

**[xtts-v2-js](https://github.com/TimaxLacs/xtts-v2-js)** (npm `1.0.0`–`1.0.6`)

Качественно другой уровень упаковки. `npx xtts-v2-js serve` сам поднимает venv, PyTorch, Coqui, XTTS-v2, FastAPI на `:5000`. Клиент: текст + reference wav + язык → WAV. 17 языков, русский в списке. Рекомендации по референсу (6–10 с, чисто, без музыки) — сразу в README. Это готовый **провайдер клона** для ECHO.

Минус: XTTS медленнее и старее Zonos/Chatterbox; в `server.py` дефолт CPU.

**[zonosjs](https://www.npmjs.com/package/zonosjs)** `1.0.0`–`1.0.8` и **zonos-client** `1.0.0`

Тот же приём, что XTTS, модель [Zyphra/Zonos](https://github.com/Zyphra/Zonos) (~7.2k ★). InnerEcho уже сидит на этом клиенте. Для русского клона это сейчас твой самый ценный артефакт: обёртка «ставится как npm, внутри Python».

Паттерн `*js serve` + клиент — повторить для Whisper/Silero/будущего TTS, не плодить три разных способа запуска.

### Мозг, биллинг, речь в проде

**[deep-assistant/api-gateway](https://github.com/deep-assistant/api-gateway)**

Коммерческий шлюз: десятки моделей, 6 поставщиков, цепочки деградации по 12–16 замен, внутренние токены, идемпотентные переводы. Есть `/v1/audio/speech` (прокси в GoAPI/OpenAI TTS) и `/v1/audio/transcriptions` (Deepinfra `whisper-large-v3-turbo`, биллинг от длительности).

Для ECHO отсюда брать:

- единый OpenAI-совместимый интерфейс мозга;
- таблицу фолбэка («голосовая маленькая модель упала → текстовая большая»);
- уже рабочий облачный STT лучше, чем Whisper `base`;
- привычку считать себестоимость запроса.

Не брать: JSON-файлы как БД на длинную дистанцию; облачный TTS без клона владельца.

**[deep-assistant/telegram-bot](https://github.com/deep-assistant/telegram-bot)**

Боевой канал: войсы, группы (отвечает только на обращение), системные промпты, Stars, TEST/PROD, переводы между пользователями. ECHO рано или поздно должен жить в Telegram. Этот бот — не ядро, а доказанный адаптер канала и биллинга.

### Память и агентные процессы

**[lightrag-mcp](https://github.com/TimaxLacs/lightrag-mcp)**  
Два read-only инструмента: готовый ответ со ссылками и сырой контекст. Валидация режима до сети. Тесты без живого HTTP. Это слот памяти ECHO с первого дня, если поднять LightRAG рядом.

**[cursor-agent-workflows](https://github.com/TimaxLacs/cursor-agent-workflows)**  
Как ты хочешь, чтобы агенты меняли код: запечатанный скоуп, параллельные стримы, отдельный checker. Для ECHO это не фича продукта, а способ его строить. Имеет смысл сразу положить те же границы в репозиторий.

**[test-resorning](https://github.com/TimaxLacs/test-resorning)**  
Конвейер «намерение → шаги → критика → синтез» без native reasoning. Для голоса целиком нельзя (долго). Для делегированной задачи («разбери почту, потом скажи коротко») — да.

**[openclaw](https://github.com/TimaxLacs/openclaw)** (форк, август 2026)  
Ты уже забрал себе upstream рук. Не игнорировать.

## Что переиспользовать буквально

Порядок от «взять завтра» к «не трогать».

1. **`zonosjs` как TTS-провайдер №1.** Не переписывать сервер. Обернуть интерфейсом `synthesize({ text, voiceRef, language })` и добавить стрим, когда понадобится.
2. **`xtts-v2-js` как провайдер №2.** Тот же интерфейс. Нужен, когда Zonos плохо ест язык или нет GPU.
3. **Паттерн npm+Python serve.** Новый STT/VAD упаковать так же. Иначе ECHO снова станет «запусти пять терминалов».
4. **`lightrag-mcp` как память.** Первый системный промпт ECHO должен уметь сходить в LightRAG до ответа.
5. **`api-gateway` как мозг с фолбэком.** Голосовому контуру — маленькая быстрая модель. Рукам — большая. Цепочка деградации уже придумана.
6. **OpenClaw как харнесс действий.** Не форкать вслепую внутрь монолита. Процесс рядом, ECHO говорит с ним как PersonalJarvis говорит с Claude Code.
7. **Telegram-бот Deep.Assistant как первый внешний канал.** Когда голосовой контур заработает на машине — тот же агент должен отвечать войсом в Telegram *твоим* тембром.
8. **cursor-agent-workflows.** Кладём skill/правила в ECHO до первой фичи.
9. **InnerEcho — только как музей и чеклист ошибок.** Код не переносить.

Не переиспользовать: `deepseek-r1:1.5b` в петле; energy VAD; запись wav на диск как единственный путь; ReAct из LangChain hub 2024 года.

## Выводы: куда ставить ECHO

### Позиция, которой нет на карте

«Сезам, но это ты» — разговор.  
«OpenClaw, но рот — твой голос» — действие.  
«isair/jarvis, но с нормальным русским и шлюзом провайдеров» — локальность.

Пустое место: **локальный (или гибридный) агент, который звучит как владелец, говорит по-русски без стыда и умеет делать дела через уже существующие руки.**

Это не конкуренция с GPT-Live. Это другая категория. GPT-Live всегда будет приятнее перебивать. ECHO выигрывает фразой: *тебе отвечает ты, и он ещё и сделал*.

### Чего не строить в первой версии

- Свой WebRTC-стек (LiveKit подождёт звонков).
- Свой магазин навыков (Pantry / Clawhub уже есть).
- Свой дом (HA).
- Свой full-duplex S2S. Веса закрыты, русский слабый, клон владельца пропадает.
- «Зеркало личности» в духе ECHOME (IRT-тесты, 256-dim d-vector) — мишура до рабочей петли.

### Архитектура, которая следует из исследования

```
          ┌──────────── голос (быстрый контур) ────────────┐
мик ─► Silero VAD ─► streaming STT ─► small LLM ─► Zonos/XTTS ─► колонка
                         │                    │
                         │            «секунду, делаю»
                         ▼                    ▼
                   LightRAG память      OpenClaw / MCP / шлюз
                   speaker profile      большая модель + тулы
```

Правила, которые уже нарушал InnerEcho и которые нельзя нарушить снова:

1. Голосовой контур не ждёт инструмент.
2. Клон — обязательный выход по умолчанию, не опция в конфиге на дне.
3. Мозг сменяется за конфигом, как модели в api-gateway.
4. Канал (динамик, Telegram, позже телефон) не знает, какой TTS внутри.
5. Память scoped на говорящего, как только в комнате появляется второй человек.

### Первый честный срез продукта

Не платформа. Одна петля, которая не врёт:

- запись референса голоса с проверкой;
- wake или кнопка;
- вопрос по-русски;
- короткий ответ *твоим* голосом;
- один реальный инструмент (время / память LightRAG / задача в OpenClaw);
- облачный и локальный мозг через один интерфейс.

Если это не стыдно включить в комнате — можно наслаивать руки. Если начать с рук и «потом озвучим», получится второй OpenClaw, и имя Эхо будет вранём.

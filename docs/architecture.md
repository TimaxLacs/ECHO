# Архитектура прототипа

Эхо — личный агент. Ядро принимает обращение, подмешивает файловую память, спрашивает мозг из цепочки и даёт ему инструменты. Канал (терминал или локальная страница) не знает, какой провайдер ответил, пока ядро само это не вернёт.

Слоты v1 живут в одном процессе Node. Контракт методов тот же, что обсуждался как `echo.v1`: `complete`, `core` / `recall` / `remember`, список и вызов инструментов, `synthesize`, `transcribe`. Отдельные процессы слотов — следующий шаг, не этот прототип: пока слот меняется вместе с ядром, резать репозитории рано.

Мозг — один клиент Chat Completions.

| Пресет | Куда | Ключ |
|---|---|---|
| `local` | base URL пользователя, по умолчанию Ollama `http://127.0.0.1:11434/v1` | не отправляется |
| `groq` | `https://api.groq.com/openai/v1` | `GROQ_API_KEY` или дом данных |
| `openrouter` | `https://openrouter.ai/api/v1` | `OPENROUTER_API_KEY` или дом данных |

Провайдер хода можно выбрать явно. Иначе идёт `slots.llm`, пока кто-то не ответит. Если модель не умеет tools, клиент один раз повторяет запрос без них.

Память — `USER.md`, `MEMORY.md` и дневник дня в доме данных. Секреты вырезаются до записи. Голос — слот TTS: Zonos на `POST /generate` или OpenAI-compatible `/audio/speech`. Пока слот `tts` пуст, ответ остаётся текстом, ход не ждёт мёртвый сервер клона.

Инструменты v1: `now`, `calc`, `memory_recall`, `memory_remember`, `files_list`, `files_read`, `files_write`, `shell`, `http_fetch`, `weather`. `shell` запускает только команды из белого списка и без оболочки. `http_fetch` не ходит на localhost, частные сети и редиректы.

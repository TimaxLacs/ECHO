# Архитектура ECHO

ECHO — не конкурент чужому ассистенту. Это **универсальный runtime**: ядро со слотами, в которые вставляется любой мозг, голос, память, канал и руки.

«Может всё» здесь не значит «в первой версии написаны все навыки мира». Значит: **ни одна способность не зашита намертво**, новую можно добавить без переписывания ядра — конфигом, плагином, MCP или уже существующим харнессом.

## Принцип

Ядро не умеет «говорить голосом Zonos» и не умеет «думать DeepSeek». Оно умеет:

1. принять обращение из любого канала;
2. вспомнить контекст;
3. вызвать мозг из цепочки фолбэка;
4. дать мозгу инструменты;
5. вернуть ответ в тот же канал — текстом или голосом владельца.

Всё остальное — реализации слотов. OpenClaw, Home Assistant, LightRAG, Telegram, Ollama, api-gateway, ElevenLabs — гости, не фундамент.

```
канал ──► ядро ──► мозг (цепочка)
           │  ▲
           │  └── память
           ▼
        инструменты ──► MCP / шелл / файлы / HTTP / OpenClaw / что угодно ещё
           │
           ▼
        голос (клон) ──► тот же канал
```

## Слоты

| Слот | Вопрос | Примеры реализаций |
|---|---|---|
| `llm` | Кто думает? | Ollama, любой OpenAI-compatible, Deep.Assistant gateway, mock |
| `stt` | Кто слышит? | Whisper, Deepinfra, облако шлюза, mock |
| `tts` | Чьим голосом отвечает? | Zonos, XTTS, ElevenLabs, OpenAI, mock |
| `memory` | Что помнит? | Файлы (`USER.md` / дневник), LightRAG, позже Mem0 |
| `tool` | Что умеет сделать? | Встроенные, MCP, плагины, внешний харнесс |
| `channel` | Откуда говорят? | CLI, HTTP, Telegram, позже микрофон / WhatsApp |
| `identity` | Кто это? | Имя, язык, референс голоса, профиль говорящего |

В каждом слоте — **цепочка**, не один поставщик. Упал Ollama — берём шлюз. Нет GPU для Zonos — облачный TTS. Нет ключей — mock, чтобы runtime вообще никогда не был мёртвым.

Это тот же приём, что в `deep-assistant/api-gateway`: таблица деградации вместо одного ретрая.

## Что ядро обещает

- Конфиг и плагины расширяют систему. Новые вендоры не требуют форка.
- Канал не знает, какой TTS внутри. Голос — свойство идентичности, не канала.
- Голосовой контур не обязан ждать инструмент: сначала короткий ответ, дело уходит в руки.
- Инструмент с риском `exec` не выполняется без явного разрешения в конфиге.
- Секреты не пишутся в память и не логируются.

## Чего ядро не обещает

- Что в комплекте уже будут все навыки OpenClaw, все устройства HA и full-duplex как у GPT-Live.
- Что один локальный файл `index.js` «просто работает как Джарвис». Так InnerEcho и остановился.

Универсальность — в стыках. Покрытие мира растёт с каждым адаптером, не с каждым `if` в ядре.

## Где жить данным

По умолчанию `~/.echo/`:

```
echo.config.json
voices/owner.wav
memory/USER.md
memory/MEMORY.md
memory/YYYY-MM-DD.md
workspace/
plugins/
skills/
```

Конфиг можно держать в репозитории проекта и указать `ECHO_HOME` или `--home`.

## Как добавить способность

1. **Конфиг** — включить уже существующий провайдер в цепочку слота.
2. **Плагин** — файл `*.mjs` с `export function register(api)`, регистрирует tool / llm / tts / channel.
3. **MCP** — строка запуска сервера в `tools.mcp`. ECHO подхватывает его инструменты как свои.
4. **Харнесс** — внешний процесс (OpenClaw, Claude Code, HA). Ядро говорит с ним как с одним инструментом `harness.run`.

Если способность не влезает ни в один слот — это дыра в ядре, её надо назвать, а не обойти копипастой.
